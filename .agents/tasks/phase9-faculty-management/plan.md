# Implementation Plan — CAMPASS Phase 9.1 Faculty Management (backend only)

Source of truth: the APPROVED design at `.agents/tasks/phase9-faculty-management/design.md` (Revision 1, verdict APPROVED in `design-review.md`). This plan sequences that design; it does not re-decide architecture. One decision carried from the review is folded in: the role_permissions seed join MUST include `AND r."institutionId" IS NULL` and an explicit conflict target (review N1 — the only non-blocking NIT), matching the frozen house style in `20261213000000_phase8_exams_slice2/migration.sql`.

Work directly on branch `main` in `c:\campusgate`. No worktree, no push, no deploy. Monorepo is npm workspaces + turbo; the API fast suite is `npm test -w @campusgate/api` (vitest, mocked DB), the live-DB suite is `npm run test:integration -w @campusgate/api`, and the API build is `npm run build -w @campusgate/api` (runs `prisma generate` + `tsc`). ### Decomposition decision
I considered restructuring the workflow tail into FEAT artifacts (permitted by the step prompt). I did NOT: this is one tightly-coupled, strictly-sequential backend slice on a single branch where every step feeds the next (schema → migration → shared catalogues → service → routes → catalogue-sync → live-DB → tenant-escape) and the suite only goes green when they land together. It does not separate into independently shippable features, so a single ordered plan run by the existing implement-and-review loop is the correct shape. The plan file above is the deliverable.
