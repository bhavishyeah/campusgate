# Implementation Plan — CAMPASS Phase 9.6 Service Requests Management (backend only)

Approved design: `.agents/tasks/phase9-service-requests/design.md` (review: APPROVED, 0 HIGH / 0 MEDIUM / 2 NIT). This plan sequences that design faithfully; it does not re-decide architecture. The two review NITs are folded in as implementer rules (NIT-1: `defaultAssigneeRole` is a free string `[A-Z0-9_]{1,64}`, no cross-table validation, `SERVICE_AGENT` is a legal value; NIT-2: `statusPatchSchema.toStatus` is `{IN_PROGRESS, PENDING_APPROVAL}` only — RESOLVED is reached via `POST /:id/resolve`, never `PATCH /:id/status`).

Branch `main`, cwd `c:\campusgate`, NO worktree, NO push. New migration dir: `20270124000000_phase9_service_requests` (the 22nd dir; next after `20270117000000_phase9_inventory`). All 21 prior frozen dirs stay byte-identical.

Build/test commands (discovered): workspace build `npm run build` (root turbo) or `npm run build --workspace @campusgate/api` (`prisma generate` + `tsc`); unit tests `npm run test --workspace @campusgate/api` (`vitest run`); live integration tests `npm run test:integration --workspace @campusgate/api` (`vitest run --config vitest.integration.config.ts`).
